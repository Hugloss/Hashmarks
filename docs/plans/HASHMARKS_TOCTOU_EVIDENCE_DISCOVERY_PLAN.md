# Filesystem check-to-use evidence discovery

**Status:** source implementation under qualification; P0 qualification incomplete.

The implementation follows the observer-only replacement plan. The normative
product boundary remains `../reference/PRODUCT_BOUNDARY.md`; the current evidence
contract is documented in `../reference/FILESYSTEM_LIFECYCLE_EVIDENCE.md`.

## Responsibility and delivery

Hashmarks describes revision-bound filesystem operations, explicit source-reference
flow, bounded canonical calls, lexical protection syntax, relevant mutators/tests,
freshness, and uncertainty. Consumers determine safety implications and further
investigation. External systems own execution, protection, admission and result
authority. The initiative is SPLIT; no universal lifecycle ontology or safety
assessment engine is admitted.

P0 covers Python filesystem evidence through existing findings, structural
locality, task evidence, service/CLI/MCP, consumer validation, and presentation.
Other languages, transactions, leases, queues, authorization, and sandbox
semantics require separate proposals grounded in measured missing primitives.

## Contract and implementation requirements

- Use `hashmarks.python-filesystem-lifecycle-observation.v1`, with one typed
  definition and semantic validator. Retain exact member revisions, source
  ranges, producer implementation/rule identity, generation and observation ID.
- Keep check and use roles distinct, including rename destinations and descriptor
  inspection versus path/name selection. Source-reference equality never proves
  runtime identity. Scope descriptors to call sites and local bindings.
- Follow qualified imports/re-exports through at most eight hops and use existing
  call resolution. Preserve shadowing, rebinding, ambiguity, unsupported dispatch,
  variadic calls, asynchronous/decorated callees and cyclic resolution as unknown.
- Observe supported structured sequencing. Do not flatten unrelated branches or
  unsupported loops/exception paths into an exact sequence. Retain useful exact
  locations when sequence qualification is unavailable.
- A supplied `dir_fd`, a lexical lock, a comment or a test result cannot become a
  child-identity guarantee. Absolute/unresolved/relative path interpretation,
  descriptor lifetime, external mutators and runtime protection remain distinct.
- Read through canonical admission and member revision authority; use the cached
  AST only for equivalent source. Detect drift before completing the observation.
  Never disclose denied supporting paths or derive facts from hidden source.
- Account for unsupported, failed and bounded work. Complete static scope is not
  negative concurrency evidence. Qualify before consumer projection.
- Default budgets: eight call hops, 64 calls/symbol, 256 references/symbol,
  256 symbols/anchor, 10,000 discovery paths, 256 returned observations. Existing
  structural scopes further constrain their projections. Bound exhaustion is
  explicit; no hidden resume or progress authority is created.
- Keep the existing `repository_findings` v1 envelope and tool arguments. Add a
  nested observation plus advisory projections. Never apply generic guarded-risk
  suppression or actionability adjudication to lifecycle observations.
- Attach task evidence only after existing owner resolution. Initial projection
  omissions remain explicit. Present qualifications independently from bounded
  positive observations. External runtime observations remain external claims.

## Required regression and native proof

The source ring must cover direct operations, aliases, Path objects, explicit
identity comparison, cross-module parameter/result forwarding, branch separation,
reassigned references, factories with distinct invocations, shadowed APIs, API
mutation, rename roles, different descriptors, descriptor-only checks, absolute
and unresolved paths, cooperating locks, positive mutators and relevant tests.

Failure cases include invalid/missing/denied source, incomplete call targets,
cycles, exhausted bounds, unsupported syntax, source drift, codec round trips,
semantic tampering, projection omissions, and reopening the same state directory.
Neither an empty packet nor an omitted observation may become a negative fact.

The native fixture coordinates check → external child replacement → deletion
with explicit pipes/events, not probabilistic stress or sleeps. It verifies that
the replacement was removed and the original retained. A visible cooperating
lock does not hide the source candidate. Process-sensitive test nodes are emitted
as singleton isolated-process selections; execution policy stays external.

Both Linux and WSL2 must pass, recording kernel/filesystem/Python conditions.
An unavailable environment is UNVERIFIED. Hashmarks independently observes the
source and separately correlates the external result using qualified revisions.

CO-R3G is mandatory for final qualification. Supply an immutable repository
snapshot/content identity, exact target paths, relevant repository-owned material,
and independently reviewed expected facts, ambiguity and environmental unknowns.
Do not expand into dependency implementations. If the reference needs semantics

Freeze development and held-out labels, eligibility, source identities, expected

An external evaluator freezes at least twelve tasks spanning identity flow,
ownership/protection and unresolved conditions, with two pinned model setups.
Match artifact, repository, prompts, tool catalog and existing evidence. The
external baseline arm withholds only the new evidence family and records that
transformation; Hashmarks gains no benchmark feature flag or model authority.

Retain exact model-delivered responses, expected pairs, failures/nonresponses,
owner and check/use correctness, unsupported assumptions, investigation quality,
and exploratory source reads. Require no correctness regression, zero unsupported
safety/exploitability claims, and at least 20% fewer median reads among correctly
completed matched pairs. Tool invocation alone is not model exposure or use.

## Candidate checks and completion

Run canonical formatting/hygiene after repairs, the focused behavior/architecture
ring, the configured type checks, and named bounded development test batches.
Use committed-lock frozen operations. Reproduce failing shards individually;
partial batches are not proof and a host timeout does not invalidate completed
batches. Do not weaken acceptance to accommodate a candidate failure.

For a persistent source candidate, build one deterministic source ZIP, compile
source once and run focused imports/tests from an independent extraction. Broader
byte-rebuild and isolated wheel/sdist proof belongs to final promotion or a
packaging-transform change. Measure matched cold/warm/incremental source and
relationship work; do not add caches or alter index representation merely to
improve a timing result.

P0 completion requires every source, native, frozen-reference, accuracy, external
usefulness and candidate-artifact obligation above. Implementation completion and
qualification completion must be reported separately. Missing external inputs
remain pending; they are never replaced by synthetic success. No production
progress ledger, policy registry or certification database is introduced.

Rollback is an external source revert and, if needed, reconstruction of disposable
CodeMap state. This feature introduces no lifecycle persistence or migration.

## Implementation and qualification record — 2026-10-15

The Python source producer, typed packet/validator, canonical CodeMap adapter,
existing-surface integration, presentation and deterministic native fixture are
implemented. The focused evidence/transport ring passes 313 tests. Focused typing
checks cover the added producer and regressions. Repository-wide typing retains
pre-existing failures and is not reported as passing.

The native fixture passes on kernel `6.18.33.2-microsoft-standard-WSL2`.
It records kernel, Python and filesystem conditions; a separate native Linux
environment remains unverified. The mandatory frozen CO-R3G snapshot, independently
labeled held-out corpus and matched external agent evaluation remain pending.
These are release-qualification gaps, not synthetic fixture successes.

Profiling identified repeated immutable AST scans. Request-local syntax summaries
preserve all repository evidence in a matched comparison against an unchanged
source snapshot. On the two-file development corpus, direct analysis decreased
from 12.17/12.56 seconds to 4.57/4.55 seconds; this is diagnostic evidence, not a
general performance guarantee. A separate call-budget repair prevents helper
re-entry from replenishing the per-symbol allowance. It retains all 23 observed
operations on that corpus, reports additional explicit bound uncertainties, and
measures 1.40/1.43 seconds. The two changes have distinct correctness contracts.

Final P0 acceptance and P1 expansion remain gated by the external qualification
obligations above. No runtime enforcement or universal lifecycle semantics have
been added.
