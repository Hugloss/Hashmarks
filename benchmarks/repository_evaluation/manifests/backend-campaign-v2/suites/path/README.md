# Genuine selected-call qualification corpus

Twelve distinct upstream problems across aiokafka, SQLAlchemy and FastStream
nominate an exact caller for bounded source observation. These are additional
capability-specific views of existing campaign problems, not twelve new problems.
The task and initial-response checks remain separate from the nominated call
query: this catalog does not measure answer-blind owner recall.

Each revision freezes a direct source segment with exact caller, callee,
direction and call-site line, plus an explicitly unresolved next receiver or
dynamic call. Source labels independently bind both declarations and each
adversarial source to exact archive bytes. Display checks require those same
facts in structured, compact and text projections. Required witnesses cover
both revisions, API, real CLI and official MCP, native facts and display facts.
Review flags remain false. Catalog membership does not establish 5/5.

| FastStream acknowledgement error | exit handler → acknowledgement helper | message acknowledgement receiver |
| FastStream empty batch publication | batch publication → command factory declaration | command receiver |
| FastStream middleware entry error | message processor → middleware-stack builder | handler receiver |

These are static source/declaration relationships. They do not prove runtime
dispatch, callback invocation, transitive reachability, concurrency behavior or
test sufficiency. External `call_or_await` implementations were excluded from
the selected positive segments; an import does not admit its dependency source.

The source-first intake also reproduced two generic defects: nested callback
calls were projected with their enclosing caller, and definition-expression
calls were attributed to the declared body. Neutral regressions retain these
failures independently of the external repositories. The additional FastStream
shutdown replay is repair evidence, not a thirteenth catalog problem.
